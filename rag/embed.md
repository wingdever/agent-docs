# embed
call embedding model to transfer text into embedding.

## embedding model
instance enum: [BGE,E5,GTE,Qwen3-Embedding]

### 训练方法：对比学习和InfoNCE
1. 训练目标：对比学习
把语义相关的 "query:text" pair 在向量空间中拉近，把无关对推远。
2. 损失函数：InfoNCE
对于一个批次内的每个查询，最大化它与正例文档的相似度，
同时最小化它与其它文档-负例的相似度。

温度参数 tau(τ) usually 0.07
控制相似度分布的"尖锐程度",影响模型对困难负例的惩罚力度
负例的质量直接决定学到的边界是否精细
--随机负例太"简单",模型可能靠非语义信号走捷径，
这正是后续微调部分要引入"难负例"的原因

### 模型生态：场景的语言和领域
opensource 家族: [BGE,E5,GTE]
差异: [训练目标,输入格式,语言覆盖,模型规格]
查询和文档必须处于同一个嵌入定义的向量空间中，
所以需要同一配置、版本、微调的模型处理文档和查询嵌入。

### 操作细节：非对称检索与前缀
1. 非对称检索
查询常是短问题或关键词，而知识库中文档块是较长的段落。
两者在长度、语义密度和表达方式上天然不对称。
Transforms官方文档明确区分对称检索和非对称检索。
2. 前缀
不少模型要求查询端加上检索指令前缀，
比如“为这个句子生成表示用于检索相关文章”。

### 向量维度
通用场景1024维是平衡性较好的默认选择。
而外部服务一般默认返回 768 维。

### 模型微调
适用场景：大量预训练模型无法区分的“近似但不同”的样本。
核心方法：难负比例对比学习
技术路线：预训练 -> 在线难负例微调 -> 对比蒸馏
